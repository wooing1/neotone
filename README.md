# NEOTONE — 배포 & 온라인 플레이 안내

`index.html` **파일 하나**가 게임 전부입니다. 이미지·사운드·라이브러리 전부 이 안에 들어 있습니다.
(PeerJS도 인라인되어 있어 실행 중 외부 스크립트를 받아오지 않습니다.)

---

## 1. 그냥 혼자 해보기

`index.html`을 더블클릭해서 브라우저로 열면 됩니다. 솔로 플레이는 이것으로 끝입니다.

## 2. 친구와 온라인으로 하기 — URL 하나 만들기

온라인 협동(최대 4인)은 **HTTPS 주소로 여는 것을 권장**합니다.
`file://`로 열어도 대체로 동작하지만, 브라우저 보안 정책상 WebRTC가 막히는 경우가 있습니다.

아래 셋 중 편한 걸 고르세요. **전부 무료이고 계정 없이 되는 것도 있습니다.**

### A. 가장 빠름 — Netlify Drop (1분, 계정 불필요)

1. <https://app.netlify.com/drop> 접속
2. `index.html`이 든 **폴더를 통째로 드래그&드롭**
3. 바로 `https://무작위이름.netlify.app` 주소가 나옵니다 → 친구에게 공유

> 계정 없이 만든 사이트는 일정 시간 뒤 사라집니다. 계속 쓰려면 무료 가입 후 claim 하세요.

### B. 오래 쓸 거면 — GitHub Pages (2분, 계정 필요)

```bash
# 이 폴더에서
git init
git add index.html
git commit -m "NEOTONE"
git branch -M main
git remote add origin https://github.com/<본인계정>/neotone.git
git push -u origin main
```

그다음 GitHub 저장소에서 **Settings → Pages → Source: `main` / `(root)`** 저장.
1~2분 뒤 `https://<본인계정>.github.io/neotone/` 로 접속됩니다.

> 웹에서 하는 게 더 편하면: 저장소 새로 만들기 → `index.html` 업로드 → Settings → Pages 설정.

### C. 같은 와이파이면 — 로컬 서버

```bash
npx serve .          # 또는  python3 -m http.server 8000
```
안내되는 `http://192.168.x.x:포트` 주소를 같은 네트워크의 친구에게 알려주면 됩니다.

## 3. 온라인 플레이 방법

**2명부터 최대 4명까지** 같이 할 수 있습니다.

1. 참가할 사람 전부 같은 주소를 엽니다
2. 타이틀에서 **`ONLINE CO-OP 2~4P`** (또는 `O` 키)
3. 한 명이 **CREATE ROOM** → 화면에 뜬 **4자리 코드**를 나머지에게 알려줍니다
4. 나머지가 각자 **JOIN ROOM** → 코드 입력 → **CONNECT**
5. 로비에 P1~P4 슬롯이 채워집니다 → **전원 READY** → 방장이 **START**

- 방장이 **P1**, 참가 순서대로 P2 → P3 → P4 슬롯이 배정됩니다.
  기체 도색이 슬롯마다 다릅니다 (P1 은백 / P2 주황 / P3 연두 / P4 보라)
- 이미 4명이면 5번째는 `방이 가득 찼습니다`로 거절됩니다
- 시작하려면 **2명 이상 + 전원 READY** 여야 합니다. 난이도는 방장이 정합니다
- 잔기·파워는 각자 따로입니다. 아이템은 먼저 줍는 사람이 가져갑니다
  (아이템은 **가장 가까운 사람**에게 끌려갑니다)
- 잔기를 다 잃으면 관전 상태가 되고, **다음 구간에서 잔기 1로 부활**합니다
- **전원이 관전이면** 게임오버 → 대기실로 함께 돌아갑니다
- 인원이 많을수록 적·보스 체력이 올라갑니다 (2인 1.35배 / 3인 1.70배 / 4인 2.00배).
  대신 아이템 드랍도 인원수만큼 늘어나서 각자 솔로만큼 파밍됩니다

### 강제 퇴장 (방장 전용)

대기실에서 방장에게만 P2~P4 슬롯 오른쪽에 **KICK** 버튼이 보입니다.
오조작을 막으려고 **두 번 눌러야** 실행됩니다 — 한 번 누르면 `한번 더` 로 바뀌고,
2초 안에 다시 누르지 않으면 저절로 풀립니다.

- 쫓겨난 사람은 `방장이 퇴장시켰습니다` 를 보고 모드 선택 화면으로 돌아갑니다
- **같은 방에는 다시 들어올 수 없습니다.** 새로고침해도 막힙니다
  (브라우저에 저장된 식별자로 판별합니다. 방을 새로 만들면 명단은 초기화됩니다)
- 사생활 보호 모드처럼 저장이 막힌 브라우저라면 창을 새로 열어 재입장할 수 있습니다.
  그때는 다시 KICK 하면 됩니다
- 게임이 시작된 뒤에는 퇴장시킬 수 없습니다. 대기실로 돌아온 뒤에 하세요

## 4. 연결이 안 될 때

온라인 연결은 **PeerJS 공개 시그널링 브로커**를 씁니다(방 코드 교환용).
연결이 성립하면 게임 데이터는 두 브라우저가 직접 주고받습니다.

| 증상 | 원인 / 해결 |
|---|---|
| `브로커 오류: network` | 공개 브로커에 못 닿는 상태입니다. 사내망·학교망에서 흔합니다 → 아래 자체 브로커 사용 |
| `방을 찾을 수 없습니다` | 코드 오타이거나, 방장이 아직 방을 안 열었거나 창을 닫은 경우 |
| `이미 사용 중인 방 코드입니다` | 드물게 코드가 겹친 경우. 나갔다가 다시 방을 만드세요 |
| **`방은 찾았지만 직접 연결이 안 됩니다`** | **가장 흔한 실패입니다. 아래 "다른 네트워크 친구와 안 될 때" 를 보세요** |
| `방이 가득 찼습니다` | 이미 4명입니다. 누군가 나가야 들어갈 수 있습니다 |

### ★★ 가장 확실한 방법 — 내 PC에 릴레이 서버 띄우기 (권장)

**연결이 안 되면 이걸 쓰세요.** WebRTC 를 아예 건너뛰고 게임 데이터를 전부 이 서버가
중계합니다. 각자 "바깥으로 나가는 WebSocket 하나"만 열면 되므로 **NAT·방화벽 문제가
아예 없습니다.** 포트 포워딩도, 공유기 설정도 필요 없습니다.

`server.js` 와 `index.html` 을 같은 폴더에 두고:

```bash
node server.js          # 기본 9000 포트. node server.js 8080 처럼 포트 지정 가능
```

> **npm install 안 해도 됩니다.** WebSocket 을 직접 구현해서 의존성이 0개입니다.
> Node 18 이상이면 그냥 실행됩니다.

**같은 와이파이라면** 이걸로 끝입니다 — 안내되는 `http://<내PC IP>:9000/` 을 공유하세요.

**친구가 다른 네트워크에 있다면**, 터미널을 하나 더 열어서:

```bash
cloudflared tunnel --url http://localhost:9000
```

`https://무작위이름.trycloudflare.com` 주소가 나옵니다. **그 주소를 친구에게 그대로
공유하면 끝입니다.** 계정도 로그인도 필요 없습니다.
(cloudflared 설치: macOS `brew install cloudflared` · Windows `winget install cloudflare.cloudflared`)

- 그 주소로 들어오면 게임이 **자동으로 릴레이를 씁니다.** 파라미터를 붙일 필요 없습니다
- 제대로 붙었는지는 **대기실에 `릴레이 서버 경유` 라고 초록색으로 표시**됩니다
- 서버 창에 누가 들어오고 나가는지 로그가 찍힙니다
- **끄면 방도 닫힙니다.** 게임하는 동안은 켜 두세요
- 이미 어딘가에 올려둔 게임(예: GitHub Pages)을 쓰고 싶다면 주소 뒤에 붙여도 됩니다:
  `https://wooing1.github.io/neotone/?ws=wss://무작위이름.trycloudflare.com/ws`

> 대역폭: 4인 기준 방장 업로드가 약 0.9Mbps 였는데, 릴레이를 쓰면 방장은
> **한 벌만 올리고 서버가 복사해서 뿌립니다.** 방장 회선 부담이 오히려 줄어듭니다.
> 대신 그만큼이 릴레이 PC의 업로드로 옮겨갑니다.

### 다른 방법 — TURN 릴레이 (서버를 못 띄울 때)

방 코드까지는 맞는데 15초쯤 뒤에 **`방은 찾았지만 직접 연결이 안 됩니다`** 가 뜬다면,
두 사람 사이에 **P2P 경로가 뚫리지 않은 것**입니다. 회사·학교·일부 모바일 회선처럼
NAT이 까다로운 곳에서 흔합니다.

이럴 때는 중간에서 데이터를 넘겨주는 **TURN 릴레이**가 필요합니다.
예전에는 PeerJS가 공용 TURN을 끼워줬지만 **현재 그 서버들은 응답하지 않습니다**
(직접 확인했습니다 — ICE 오류 701). 그래서 릴레이는 직접 지정해야 합니다.

**무료 TURN 발급받기 (2분)**

1. <https://dashboard.metered.ca/> 또는 Cloudflare Realtime(TURN) 에서 무료 가입
2. TURN 자격증명(주소 / 아이디 / 비밀번호)을 받습니다 (무료 한도로 충분합니다)
3. **참가자 전원**이 주소 뒤에 붙여서 접속합니다:

```
https://wooing1.github.io/neotone/?turn=turn:주소:443?transport=tcp|아이디|비밀번호
```

- 구분자는 `|` 세 칸입니다: `주소|아이디|비밀번호`
- 여러 개를 넣으려면 콤마로 잇습니다
- **`?transport=tcp` 로 443 포트를 쓰는 걸 권합니다** — UDP를 막는 회선도 뚫립니다
- 자체 브로커(`?peer=`)와 같이 쓸 수 있습니다: `?peer=...&turn=...`

> 릴레이를 꽂으면 게임 데이터가 그 서버를 거쳐 갑니다. 핑이 조금 늘지만
> 연결 자체가 안 되던 회선에서 붙습니다.

**릴레이 없이 먼저 해볼 것**

- 둘 다 **휴대폰 핫스팟**으로 옮겨서 시도 (사내망 문제인지 바로 확인됩니다)
- **회선이 가장 무난한 사람이 방장**을 맡기 (집 인터넷 > 회사 > 모바일)
- VPN을 켜 두었다면 끄고 시도

### 자체 브로커 쓰기

공개 브로커가 막힌 환경이라면 브로커를 직접 띄울 수 있습니다.

```bash
npx peerjs --port 9000 --key peerjs --path /myapp
```

그리고 **참가자 전원**이 주소 뒤에 파라미터를 붙여서 접속합니다.

```
https://내주소/index.html?peer=브로커주소:9000:myapp
```

> 브로커는 방 코드 교환만 중계합니다. 게임 데이터는 여전히 P2P로 직접 오갑니다.

## 5. 알아두면 좋은 것

- **방장(호스트)이 게임 월드를 계산합니다.** 탄·적·보스·아이템이 전부 방장 쪽에서 돌아가고
  30Hz로 참가자 전원에게 전송됩니다(1인당 약 39KB/s, **4인이면 방장 업로드 약 117KB/s ≈ 0.9Mbps**).
  그래서 **회선이 가장 좋은 사람이 방을 만드는 게 유리합니다.**
- 참가자끼리는 직접 연결하지 않고 전부 방장을 거칩니다(스타 구조).
- 각자 자기 기체 움직임과 자기 피격은 로컬에서 판정하므로, 핑이 있어도 **조작 지연은 없습니다.**
- 방장이 창을 닫으면 게임이 끊깁니다.
